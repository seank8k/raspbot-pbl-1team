# 03 · Codex 작업 기록 (2026-11-05)

기록: Codex · 앞 기록: [02 진행상황](02-진행상황-2026-11-05.md)

## 현재 상태 — 다음 작업 전에 먼저 읽기

- **라즈봇은 배터리 방전으로 꺼져 있음** — 조원 확인. 현재 서버도 사용할 수 없다.
- **끝 정지 수정까지는 라즈봇에 반영했다.** 당시 자동 시험 168개 통과 후 서버·카메라·인식·블랙박스 시작을 확인했다.
- **카메라 기본 45° 자동 정렬과 잘못된 재출발 로그 수정은 노트북에만 있다.** 라즈봇에는 아직 복사하지 않았다. 실제 카메라를 45°로 움직이지도 못했다.
- 완주·정지선에서 바르게 멈추기·카메라 실제 방향은 아직 성공으로 확인하지 않았다. 자동 시험 통과와 실제 주행 성공은 구분한다.
- 비밀번호는 이 기록에 저장하지 않는다.

## 1. 로그와 블랙박스로 확인한 문제

### 줄을 자주 놓친 뒤 정지

- 처음 확인한 주행은 `10초 안에 줄 놓침 3번` 규칙으로 정지했다. 앞 두 번은 줄을 다시 찾았지만 세 번째에 정지했다.
- 다른 회차는 줄이 오른쪽으로 빠졌는데 당시 찾기는 왼쪽 회전으로 고정돼 복구에 실패했다.
- 연결 해제 기록은 정지 후에 발생했다. 처음 조사한 정지를 통신 끊김 때문이라고 결론 내리지 않았다.

### 장애물 앞 정지와 재출발

- 상자를 **136mm**에서 감지해 멈춘 기록과 실제 상자가 있는 영상을 확인했다. 명령 완료 시간만으로 충돌이 없었다고 단정하지 않았다.
- 상자를 치워도 재출발하지 않은 회차가 있었다. `MAX_KNOWN = 800` 때문에 **800mm 초과 값은 치워짐 확인에 쓰지 않는 것**이 원인 후보였다. 당시 먼 거리값이 기록되지 않아 그 회차의 원인은 확정하지 못했다.
- 이후 주행에서는 치워짐 1초를 확인하고 재출발한 기록도 있었다. 모든 장애물 정지·재출발이 같은 문제는 아니다.

### 끝에서 똑바로 정지하지 못함

- 마지막 부근에서 `1111`이 약 **0.04~0.09초**만 나타난 기록이 있었다. 기존 `1111` 정지는 **0.3초** 동안 유지되어야 했다.
- 코너 진입·회전 중에는 `1111`이 나와도 정지선 판단을 하지 않고 해당 동작을 계속했다.
- 따라서 도착 정지 대신 **코너 회전 1.5초 실패** 또는 **줄 놓침 3번**으로 멈춘 회차가 있었다.
- 이때 정지 명령 완료 기록은 약 **0.004~0.006초**였다. 로그상 문제는 정지 판단 시점이며, 실제 제동 거리까지 측정한 것은 아니다.
- 녹화 중인 AVI의 시간 이동으로 뽑은 마지막 장면은 시각이 맞지 않았다. 해당 추출 이미지는 삭제했고, 마지막 위치를 확정하는 증거로 사용하지 않았다. 순차 재추출은 연결이 끊겨 완료하지 못했다.

## 2. 수정하고 라즈봇에 반영한 내용

지시서부터 수정하고 프로그램·시험을 맞췄다.

| 항목 | 반영한 동작 |
|---|---|
| 줄 찾기 | 마지막으로 줄을 본 쪽으로 찾는다. 왼쪽 감지 뒤에는 왼쪽, 오른쪽 감지 뒤에는 오른쪽. 회전 속도 40·최대 1초 유지 |
| 코너 진입 | 감지 뒤 속도 40으로 0.1초 전진한 다음 제자리 회전. 회전 제한 1.5초 유지. 실물 검증 중인 시험값 |
| 장애물 진단 | 대기 중 0.2초마다 실제 거리·읽기 상태·출발 불가 이유·치워짐 확인 남은 시간을 기록 |
| 코너 집계 | 제자리 회전 뒤 가운데 칸을 연속 2번 읽고 따라가기로 복귀했을 때 1번. 회전 시작·실패·일반 줄 찾기 복귀는 세지 않음 |
| 마지막 구간 | 코너 5개 통과 즉시 속도 최대 40. 엄지척으로도 넘기지 않음 |
| 정지선 감지 준비 | 마지막 구간에서 따라가기 중 가운데 칸이 0.3초 연속 확인되면 감지 준비. 대기 시간은 포함하지 않음 |
| 마지막 정지선 | 감지 준비 뒤 `1111` 연속 2번이면 코너 진입·회전·줄 찾기보다 먼저 네 바퀴 0 |
| 초기화 | 새 라인 출발 때 코너 집계·도착 감지 상태 초기화. 기존 정지 후 재출발 절차 유지 |

**유지한 안전 조건:** 줄 놓침 10초 안에 3번이면 정지, 센서·영상·제어 오류 정지, 장애물 150mm 이하 정지, 치워짐 200mm 초과 1초 확인. 측정하지 않은 거리 범위를 임의로 넓히지 않았다.

### 시험과 적용 이력

| 단계 | 확인한 결과 |
|---|---|
| 줄 찾기·코너 진입·장애물 로그 수정 | 라인 78 + 장애물 38 + 사람/STOP 18 + 손 모양 15 = 로컬 149개 통과 |
| 첫 라즈봇 반영 | 위 149개 + 웹 판단 통합 5개 = 154개 통과 |
| 끝 정지 수정 | 기존 149개 + 끝 정지 12개 = 로컬 161개 통과 |
| 끝 정지 라즈봇 반영 | 라인 78 + 끝 정지 12 + 장애물 38 + 사람/STOP 18 + 손 모양 15 + 웹 판단 통합 7 = **168개 통과** |

마지막 서버 시작 당시 HTTP 200·카메라 640×480·두 인식 모델·블랙박스 시작을 확인했다. 조원에게 카메라 화면과 실제 주행 확인을 요청했다. 이후 배터리 방전으로 종료됐다.

## 3. 마지막 주행 로그에서 추가 확인한 것

대상: 라즈봇의 `results/webabb-20261105-211625.log`.

- 코너 1개 또는 3개를 센 뒤 **장애물 대응 중 정지**한 회차가 있었다. 아직 끝 정지 조건을 검증한 주행으로 볼 수 없다.
- 코너 진입 뒤 줄을 읽지 못해 1.5초 제한으로 멈춘 회차도 남아 있다. 코너 진입 0.1초 변경이 모든 경우를 해결한 것은 아니다.
- 장애물 정지 뒤 줄이 안 보이면 옆걸음 찾기를 시작하려고 한다. 이때 기존 줄 놓침 기록에 새 찾기가 더해져 **3회 제한으로 즉시 취소**된 회차가 있었다.
- 취소된 경우에도 기존 코드가 먼저 `OBST 다시 출발`을 출력했다. 실제 출발과 다른 로그이므로 아래 미반영 수정본에서 고쳤다.
- 코너 회전 도중 장애물로 멈추면 기존 규칙대로 미완료 회전 동작을 버린다. 코너 집계가 실제 위치와 맞는지 계속 확인해야 한다. 완료되지 않은 코너를 임의로 통과 처리하지 않았다.
- 1초 찾기·0.9초 옆걸음·줄 놓침 3회 제한을 임의로 늘리거나 없애지 않았다.

## 4. 노트북에만 있는 최신 수정 — 아직 라즈봇 미반영

### 카메라 기본 자세 45°

- 조원 요청은 처음 위로 약 5°였다가 **위로 20°**로 바뀌었고, 라인 버튼을 누를 때 기본 자세로 맞추도록 요청했다.
- 이전 기준 25°에서 20° 올려 **위아래 서보 45°**로 정했다. 기존 기록에 각도 숫자가 클수록 위로 향한다고 확인돼 있었다.
- 새 라인 시작마다 서보 2번에 45°를 다시 명령한다. 좌우 서보는 바꾸지 않는다.
- `tools/servo_center.py`와 같은 **0.5초 동안 바퀴를 0으로 유지**한 뒤 새 센서값으로 출발 여부를 확인한다. `sleep`으로 제어 스레드를 막지 않는다.
- 서보 명령이 실패하면 출발하지 않는다. 실제 각도 읽기 기능이 없으므로, 명령 성공이 실제 자세 확인을 대신하지 않는다.
- 기계 조립 기준을 맞추는 `tools/servo_center.py`의 기존 90°/25° 값은 바꾸지 않았다.
- 드라이버 압축 파일에서 서보 레지스터 `0x02`, 데이터 `[서보 번호, 각도]`를 확인했다. **실제 카메라 45° 조정은 아직 실행하지 못했다.**

### 재출발 로그 수정

- 옆걸음 찾기가 줄 놓침 3회 제한으로 취소되면, `OBST 다시 출발` 대신 **`OBST 재출발 취소`와 정지 이유**를 기록한다.
- 정지 조건 자체는 유지한다. 이 수정은 안전 제한을 풀어 재출발시키는 변경이 아니다.

### 최신 수정의 검증 상태

- `missions/webabb.py`와 `tools/test_line_changes_web.py` **파이썬 문법 검사 통과**.
- 웹 판단 통합 시험을 기존 7개에서 **11개로 확장했지만 아직 실행하지 못했다.** 노트북에 Flask가 없고, 라즈봇은 배터리 방전으로 꺼졌다.
- 따라서 위의 **168개 통과는 이전에 라즈봇에 반영한 끝 정지 버전의 결과**다. 카메라 자동 정렬·재출발 로그 수정 버전까지 통과했다고 보면 안 된다.

## 6. 충전 후 이어서 할 일

1. 전원·핫스팟 연결과 SSH 접속 확인. 마지막 서버 로그와 블랙박스를 먼저 보존한다.
2. 원격 파일이 바뀌었는지 비교하고 백업한 뒤, 카메라 45° 자동 정렬·재출발 로그 수정본을 복사한다.
3. 바퀴 없이 웹 판단 통합 **11개**와 관련 회귀 시험을 실행한다. 실패하면 고친 뒤 다시 확인한다.
4. 카메라 45°가 실제로 원하는 위쪽을 보는지 조원에게 확인한다.
5. 바닥·사방 1m 안전 확인 후 서버를 켠다. 라인 버튼에서 먼저 카메라가 정렬되고 대기 뒤 출발하는지 확인한다.
6. 장애물 없는 같은 코스에서 코너 5개 집계와 정지선 감지 준비를 확인하고, 마지막 정지를 3회 반복한다. 장애물 때문에 중단한 주행은 완주 시험과 구분해 기록한다.
7. 장애물 재출발은 상자를 앞 40cm로 옮겨 2초 유지하는 비교 시험과 1m·1.5m 거리 측정을 진행한다. 검증 전에는 800mm 제한을 확대하지 않는다.
