이상. 가장 큰 결함은 자율 모드를 끄는 조건이 기존 웹 조종의 신호·누름 번호·자리 관리에 어떻게 연결되는지 정해지지 않았다는 점입니다. 아래 항목을 지시서에서 먼저 확정해야 합니다.

1. **[치명] ‘화면 신호 1초 끊김’에 해당하는 요청이 없다.**  
   **근거:** `specs/04-line-tracer.md:25,48,68`, `missions/webabb.py:39,41,280,413,701`, `missions/webabb/index.html:119,174,211`.  
   **시나리오:** 현재 `/api/status`는 0.5초마다 자리를 갱신하지만, 이동 유효기간은 `/api/move`의 수신 시각으로 판단한다. 라인 모드에서는 방향 버튼을 누르지 않으므로 이동 신호가 없다. 기존 판정을 쓰면 정지하고, 이를 우회하면 별도 1초 정지가 구현되지 않는다. 자리 만료는 3초라 대체할 수 없다.  
   **고칠 방법:** 라인 모드 소유자·자리 세대에 연결된 생존 요청과 서버의 마지막 유효 수신 시각을 명시한다.

2. **[치명] 정지 뒤 늦게 도착한 ‘라인 켜기’를 막는 규칙이 없다.**

   **고칠 방법:** 라인 시작에도 순번·새 누름 번호·자리 세대를 적용하고, 모든 안전 정지가 이전 시작 요청을 무효화하도록 정한다.

   **고칠 방법:** 읽기 지연 상한과 고장 주입 시험을 정하고, 같은 버스가 막힌 경우의 정지는 독립된 보드 정지 기능이나 물리 차단으로 검증한다.

4. **[치명] 기존 안전 구조를 ‘그대로 쓰면 된다’는 전제가 실물 검증보다 앞서 있다.**

10. **[높음] 통신 성공과 센서 정상 갱신을 혼동한다.**

16. **[높음] ‘아무 칸이나 줄을 보면 복귀’는 잘못된 줄과 반복 찾기를 허용한다.**

18. **[높음] 직각 실패와 마지막 방향 기억의 상태 전이가 빠졌다.**

    **고칠 방법:** 배터리·바닥별 회전각, 차체 전체 이동 범위, 후진거리, 정지거리를 측정해 허용 범위를 정한다.

20. **[높음] 07에서 안전 정지가 찾기 동작에 의해 풀릴 수 있다.**  
    **근거:** `specs/04-line-tracer.md:4,23,68,70`, `specs/03-blackbox.md:5,55`.  
    **시나리오:** 장애물 때문에 멈춘 동안 라인 찾기 시간이 계속 흐르면, 장애물이 사라지자 후진 단계가 실행될 수 있다. 사람 STOP과 수동 인계가 겹칠 때 누가 우선인지, 안전 정지 해제 후 자동으로 다시 출발하는지도 없다.  
    **고칠 방법:** 모든 이동 출력보다 안전 정지를 우선하고, 정지 시 라인 상태·타이머·시작 권한을 취소할지 유지할지 명시한다.

21. **[중간] ‘0.02초 주기’와 속도 60·80의 추종 가능성이 검증되지 않았다.**  
    **근거:** `specs/04-line-tracer.md:44,54,65,72`, `missions/webabb.py:511,529`.  
    **시나리오:** 현재 루프는 처리 후 0.02초 쉬므로 실제 간격은 처리시간을 더한 값이다. 속도 값은 cm/s가 아니다. **추정:** 좁거나 비스듬한 줄을 두 읽기 사이에 건너뛸 수 있다. ‘완만·세게’의 바퀴 비율도 미정이고 경계에서 좌우로 번갈아 검출될 때 진동을 막는 조건이 없다.  
    **고칠 방법:** 실제 최대 읽기 간격·이동속도·센서 간격·테이프 폭을 측정하고, 회전 비율과 전환 안정 조건을 확정한다.

22. **[중간] ‘영상 멈춤’은 휴대폰에서 보는 영상의 멈춤을 감시하지 않는다.**  
    **근거:** `specs/04-line-tracer.md:10,26,47`, `missions/webabb.py:187,203,204,205,416`, `missions/blackbox.py:38,191`.  
    **시나리오:** 현재 영상 나이는 서버가 JPEG를 만든 시각이다. 휴대폰 영상만 멈추고 상태 요청은 살아 있으면 서버는 정상으로 본다. `--no-camera`에서는 나이가 항상 0이므로 정지가 비활성화된다. 블박의 영상 없음 기준도 0.3초로 별개다.  
    **고칠 방법:** 서버 촬영·브라우저 수신·블박 저장의 신선도를 구분하고, 라인 모드에서 `--no-camera`를 허용할지 정한다.

23. **[중간] 블박과 ‘상관없음’이라는 주장은 부하 검증을 대신하지 못한다.**  
    **근거:** `specs/04-line-tracer.md:72,83`, `specs/03-blackbox.md:46,53,104`, `log.md:20`, `missions/blackbox.py:69,244`.

    **고칠 방법:** 라인센서 읽기·영상 전송·블박 파일 교체·삭제·느린 쓰기를 함께 실행해 제어 간격, 정지시간, 온도를 확인한다.

24. **[중간] 성공 기준의 시간 시작점과 시험 범위가 불명확하다.**  
    **근거:** `specs/04-line-tracer.md:35,37,38,41,81,82,83`, `specs/webabb.md:52,53`.  
    **시나리오:** 줄 끝 정지는 ‘켜고 약 2.5초’라 출발부터인지 줄 소실부터인지 불명확하다. 0.5초는 손가락 누름부터인지 서버 수신부터인지, 1.5초는 와이파이 차단부터인지 마지막 요청부터인지 정해지지 않았다. 영상 0.8초 소실·센서 실패·값 고정·늦은 시작 요청·감시 복구 시험도 빠졌다.  
    **고칠 방법:** 사건 발생·서버 판정·0 출력 완료·실제 바퀴 정지를 구분하고, 고장별 시험 조건·횟수·최대 허용값을 지정한다.

25. **[중간] ‘완주 5/5’와 ‘찾기 4/5’로 당일 공개 코스 대응을 판정할 수 없다.**

    **고칠 방법:** 연습·미사용 코스 평가를 나누고, 코스 조건 범위·개입 금지 범위·완주 판정·찾기 실패의 허용 이유를 명시한다.

26. **[중간] 바꿔 볼 값이 안전 한계와 충돌한다.**  
    **근거:** `specs/04-line-tracer.md:44,45,51,52,53,54`, `AGENTS.md:31,39`.
