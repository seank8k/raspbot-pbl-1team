# 지시서 06 · 사람 · STOP 표지판 찾으면 STOP 표시

> 틀: `specs/00-template.md`. 「조원 결정」은 1조가 정한 것, 「(질문)」은 아직 조원이 정하지 않은 칸 — 정해지기 전에는 만들지 않는다.
> 큰 목표: 03 블박 → 04 라인트레이서 → 05 장애물 정지 → **06 사람 STOP 표시** → 07 자율주행에서 합친다.

## 목표
라즈봇 카메라로 **사람**과 **STOP 표지판**을 찾으면 **웹 화면에 STOP을 표시**한다. 바퀴를 멈추는 것은 07에서 합친다.

## 왜
- 07 자율주행에서 사람 · STOP 표지판 앞에서 멈추기 위한 「보는」 부분을 먼저 따로 만들고 잰다 (인식 속도 · 거리 · 열).
- 04 · 05는 센서만 썼다 → 카메라로 판단하는 첫 기능.

## 정해진 것
| 무엇 | 내용 | 누가 정함 |
|---|---|---|
| 찾을 것 | **사람(`person`, COCO 0번)** · **STOP 표지판(`stop sign`, COCO 11번)** | 조원 결정 (2026-11-05) |
| 모델 | **YOLO26n** — Hugging Face `Ultralytics/YOLO26`의 `yolo26n.pt` (5.3MB · AGPL-3.0) → ONNX로 바꿔 라즈봇 OpenCV DNN으로 돌림. 예전 리뷰(`docs/reviews/06-yolo26.md`)는 「YOLO11n 유지」 권고였지만 조원이 YOLO26n으로 정함 → 리뷰 조건(**라즈봇 OpenCV에서 실제로 읽히고 돌아가는지 먼저 확인**)을 시작 전 조건으로 둠 | 조원 결정 (2026-11-05) |
| 06의 범위 | **화면 표시만.** 바퀴는 건드리지 않는다 | 진행 계획 (03 · 04 · 05 머리말 「06 사람 STOP 표시」) |
| 07에서 합칠 때 | 사람 STOP은 라인 모드를 **끄고** 자동으로 다시 출발하지 않는다 | 지시서 04 「07 자율주행과 합칠 때」 |
| 라즈봇 설치 | 라즈봇에는 아무것도 새로 설치하지 않는다 (OpenCV는 이미 있음 · `pip install` 금지) | AGENTS.md |

## 성공 기준 (숫자로) — (질문) 숫자는 조원이 정함
| 무엇 | 기준 | 횟수 |
|---|---|---|
| 나타남 → STOP 표시 | 사람(또는 표지판)이 카메라 앞에 나타난 순간(바깥 영상) → 화면에 STOP **(질문) 몇 초 안** (리뷰 #2 치명) | (질문) |
| 사람 찾는 거리 | 라즈봇 카메라에서 **(질문) 몇 cm ~ 몇 cm** 안의 서 있는 사람 | (질문) |
| STOP 표지판 찾는 거리 · 크기 | 표지판 **(질문) 크기(인쇄 몇 cm)** 를 **(질문) 몇 cm** 안에서 | (질문) |
| 잘못 켜짐 | 사람 · 표지판이 없는 코스 영상에서 STOP이 켜지는 횟수 **(질문)** | (질문) |
| 같이 돌릴 때 | 웹 영상 · 블박 · 라인 · 장애물을 다 켠 채 인식 속도 · 제어 한 바퀴 최대 0.1초 유지 · 온도 | **(질문) 몇 분 · 몇 °C 이하** (리뷰 #7) |

## 안전
- 06은 바퀴를 움직이지 않는다 (사람이 카메라 앞에 서는 시험이라 바퀴는 꺼 둔다 — `--dry` 또는 상자 위).
- 사람 시험 영상 · 사진은 **레포에 올리지 않는다** (`.gitignore` · 얼굴).
- 쿨러 없음: 오래 돌릴 때 온도를 기록하고 80°C에 가까우면 멈춘다.

## 시작 전 조건 (만들기 전에 잰다 · 바퀴 안 움직임)
1. **ONNX 만들기**: `yolo26n.pt` → ONNX (입력 320 · 640 · 크기 고정 · batch 1). **바꾸는 곳은 라즈봇이 아닌 다른 컴퓨터** — 바꾼 도구 버전 · 옵션 · 파일 SHA-256을 `models/README.md`에 적는다. → **2026-11-05 완료** (노트북 · 조원: 「HF 것을 ONNX로 변환」 · 결과 표 참고)
2. **라즈봇 OpenCV로 읽히는가**: 라즈봇에서 불러오기 · 첫 추론 · 출력 모양 확인 (리뷰 #5: 출력 형식이 YOLO11과 다를 수 있음). 안 읽히면 06은 YOLO11n 320으로 돌아갈지 조원에게 묻는다. → 노트북 OpenCV 5.0에서는 읽힘 · 출력은 YOLO11과 같은 `(1, 84, N)` · `TopK` 없음. **라즈봇(OpenCV 4.10) 확인 대기** (라즈봇이 꺼져 있었음)
3. **속도**: 320 · 640 각각 단독 60초 추론 속도 (중간 · 최대).
4. **사진으로 확인**: 사람 · STOP 표지판 사진에서 실제로 찾는지 (확신도 기록).

## 바꿔 볼 값
- 입력 크기 320 → 640 (STOP 표지판처럼 작은 것을 더 잘 봄 · 대신 느림)
- 인식 횟수 초당 10장 → 5장 (CPU 여유)

## 설계 — Claude 제안 (조원 승인 대기)
```
카메라 스레드 (webabb.py 지금 그대로 · 영상 · 블박)
   └─ 최신 장면 1장 + 찍은 시각만 넘겨줌 (밀린 장면은 버림)
인식 스레드 (새로 · missions/detect.py) — 초당 최대 10번
   └─ YOLO26n ONNX (OpenCV DNN) → person · stop sign 박스 + 확신도 + 「찍은 시각 · 인식 끝난 시각」
웹 화면
   └─ 카메라 위에 박스 · STOP · 인식 나이(몇 초 전 결과인지)
```
- 리뷰 #1 · #8: 카메라와 인식을 **다른 스레드**로 → 인식이 느려도 영상 · 제어가 안 막힘 · 결과마다 시각을 붙여 「오래된 결과」를 알 수 있게.
- `missions/detect.py`: 바퀴 · 웹을 모른다 → 사진으로 자동 시험 · 07에서 재사용.

## 만드는 순서
1. 시작 전 조건 1 ~ 4 (바퀴 없이)
2. 조원이 위 (질문) 칸을 정함 → 이 지시서 고침
3. `missions/detect.py` + 사진 자동 시험 (`tools/test_detect.py`)
4. 웹 화면에 박스 · STOP (`webabb.py --dry`)
5. 같이 돌리기 시험 (웹 영상 · 블박 · 라인 · 장애물 · 인식)
