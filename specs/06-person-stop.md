# 지시서 06 · 사람 · STOP 표지판 찾으면 STOP 표시

> **인식 상태 상시 표시 — 2026-11-06 조원 요청:** 영상 아래에 사람·STOP 상태를 각각 항상 표시한다. 감지됨(확신도 0.65 이상), 약하게 감지(정지 기준 미달), 감지 안 됨을 구분하고 확신도를 표시한다. 꺼짐·준비 중·오류·오래된 결과·통신 끊김은 확인 불가로 표시한다. 실제 주행 여부와 정지 이유를 함께 보여준다. 인식·정지·재출발 규칙은 그대로 둔다.

> **웹 인식 확인 알림 — 2026-11-06 조원 요청:** 영상 바로 아래에 빨간 「STOP 표지판을 봤어요 · 확신도 NN%」 알림을 표시한다. 최신 정상 인식 결과의 stop sign 점수가0.65 이상일 때 표시하고, 사람만 보이거나 표지판 없음·인식 오류/끊김·자리 상실이면 지운다. 표지판 검출을 알려 주는 표시이며 실제 라인 정지는 기존0.65 연속2번·3초 규칙을 유지한다.

> **카메라 수동 조정 — 2026-11-06 조원 「살짝 더 올려보자」:** 최종 위아래 서보2번 명령값 **5°**. 처음에는 마지막25° 기록을 기준으로30°를 명령했으나 실화면에서 과도하게 올라가 철회했다. 0° 화면이 조정 전과 거의 같았고5°가 소폭 상향임을 전후사진으로 확인했다. 실제 각도 읽기는 없으므로 명령값과 육안 확인을 구분한다. 바퀴·라인 판단·인식 기준0.65는 바꾸지 않는다. 시작할 때 자동 정렬은 추가하지 않는다.

> **현재 통합 — 2026-11-06 조원 요청:** 최신 라인 판단(1111 즉시 정지·연속1초 도착, 놓침 횟수 정지 제거)에 기존 사람·STOP 인식을 켠다. STOP은 3초 멈춘 뒤 재출발하며 같은 표지판은 출발 뒤5초 무시한다. 사람은 보이는 동안 멈추고 사라진 지1초 뒤 재출발한다. 확신도0.65·새 결과 연속2번을 유지한다. 장애물·인식지연·비상정지·1111 도착이 남아 있으면 출발하지 않는다. 사람/STOP 해제 시 현재 줄로 다시 판단하며, 되돌렸던 사람/STOP 뒤 옆걸음·코너 이어서 기능은 추가하지 않는다. 손 모양은08의 출발/정지 전용 모드로 연결한다. 수동 조종의 적용 범위는 기존대로다. 아래의 서로 충돌하는 과거 설명보다 이 문단과04의 현재 규칙을 우선한다.

> 틀: `specs/00-template.md`. 「조원 결정」은 1조가 정한 것, 「(질문)」은 아직 조원이 정하지 않은 칸 — 정해지기 전에는 만들지 않는다.
> 큰 목표: 03 블박 → 04 라인트레이서 → 05 장애물 정지 → **06 사람 STOP 표시** → 07 자율주행에서 합친다.

## 목표
라즈봇 카메라로 **사람**과 **STOP 표지판**을 찾아 웹에 표시하고, 라인 따라가기 중 정지·재출발을 제어한다.

## 왜
- 07 자율주행에서 사람 · STOP 표지판 앞에서 멈추기 위한 「보는」 부분을 먼저 따로 만들고 잰다 (인식 속도 · 거리 · 열).
- 04 · 05는 센서만 썼다 → 카메라로 판단하는 첫 기능.

## 안전
- 사람을 카메라 앞에 세우는 인식 시험은 바퀴 없이 `--dry`로 한다. 실제 통합 주행은 AGENTS의 바닥·사방1m 확인 뒤 실행한다.
- 사람 시험 영상 · 사진은 **레포에 올리지 않는다** (`.gitignore` · 얼굴).
- 쿨러 없음: 오래 돌릴 때 온도를 기록하고 80°C에 가까우면 멈춘다.

## 시작 전 조건 (만들기 전에 잰다 · 바퀴 안 움직임)
1. **ONNX 만들기**: `yolo26n.pt` → ONNX (입력 320 · 640 · 크기 고정 · batch 1). **바꾸는 곳은 라즈봇이 아닌 다른 컴퓨터** — 바꾼 도구 버전 · 옵션 · 파일 SHA-256을 `models/README.md`에 적는다. → **2026-11-05 완료** (노트북 · 조원: 「HF 것을 ONNX로 변환」 · 결과 표 참고)
2. **라즈봇 OpenCV로 읽히는가**: 라즈봇에서 불러오기 · 첫 추론 · 출력 모양 확인 (리뷰 #5: 출력 형식이 YOLO11과 다를 수 있음). 안 읽히면 06은 YOLO11n 320으로 돌아갈지 조원에게 묻는다. → 노트북 OpenCV 5.0에서는 읽힘 · 출력은 YOLO11과 같은 `(1, 84, N)` · `TopK` 없음. → **2026-11-05 라즈봇 OpenCV 4.10에서도 읽힘 · 완료** (결과 표)
3. **속도**: 320 · 640 각각 단독 60초 추론 속도 (중간 · 최대). → 2026-11-05 단독 20초 · 10초로 먼저 잼 (결과 표) · 같이 돌릴 때 속도는 만드는 순서 5에서
4. **사진으로 확인**: 사람 · STOP 표지판 사진에서 실제로 찾는지 (확신도 기록).

## 바꿔 볼 값
- 입력 크기 320 → 640 (STOP 표지판처럼 작은 것을 더 잘 봄 · 대신 느림)
- 인식 횟수 초당 10장 → 5장 (CPU 여유)

## 설계 — Claude 제안 (조원 승인 대기)
```
카메라 스레드 (webabb.py 지금 그대로 · 영상 · 블박)
   └─ 최신 장면 1장 + 찍은 시각만 넘겨줌 (밀린 장면은 버림)
인식 스레드 (새로 · missions/detect.py) — 초당 최대 10번
   └─ YOLO26n ONNX (OpenCV DNN) → person · stop sign 박스 + 확신도 + 「찍은 시각 · 인식 끝난 시각」
웹 화면
   └─ 카메라 위에 박스 · STOP · 인식 나이(몇 초 전 결과인지)
```
- 리뷰 #1 · #8: 카메라와 인식을 **다른 스레드**로 → 인식이 느려도 영상 · 제어가 안 막힘 · 결과마다 시각을 붙여 「오래된 결과」를 알 수 있게.
- `missions/detect.py`: 바퀴 · 웹을 모른다 → 사진으로 자동 시험 · 07에서 재사용.

## 만드는 순서
1. 시작 전 조건 1 ~ 4 (바퀴 없이)
2. 조원이 위 (질문) 칸을 정함 → 이 지시서 고침
3. `missions/detect.py` + 사진 자동 시험 (`tools/test_detect.py`)
4. 웹 화면에 박스 · STOP (`webabb.py --dry`)
5. 같이 돌리기 시험 (웹 영상 · 블박 · 라인 · 장애물 · 인식)
