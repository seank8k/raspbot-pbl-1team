1. **[치명] 「20cm 밖」을 「사람이 안전한 곳으로 물러남」으로 취급한다.**  
   **근거:** `specs/05-obstacle-stop.md:19,32,35`.

   **고칠 방법:** 사람이 접근한 뒤에는 새 출발 확인을 받거나, 자동 출발을 허용할 출입 통제 조건을 조원이 정한다.

2. **[치명] 무기한 대기 중 들어 옮긴 로봇도 출발 권한을 유지한다.**  
   **근거:** `specs/05-obstacle-stop.md:19,20,21`; `missions/webabb/index.html:237`.  
   **시나리오:** 켜진 조종 화면을 둔 채 로봇을 들어 옮긴다. 센서 아래에 줄이 보이고 앞이 비면 들고 있는 중이나 내려놓는 순간 출발할 수 있다. 「라인 계속」은 브라우저 타이머이므로 사람이 실제로 지켜본다는 보장이 아니다.  
   **고칠 방법:** 들어 옮기기 전 라인 해제를 필수 절차로 정하고, 장기 대기 뒤 출발 권한을 언제 취소할지 정한다.

3. **[치명] 재출발 판단 도중 들어온 정지를 출력 직전에 재확인하지 않는다.**  
   **근거:** `specs/05-obstacle-stop.md:73,77`; `missions/webabb.py:416,506,543,554`.  
   **시나리오:** 안전 검사를 통과한 뒤 초음파·라인센서를 읽는 동안 비상정지나 방향 첫 누름이 도착한다. 현재 출력 직전 검사는 감시 개입과 처리시간만 확인하므로, 0.1초 이내라면 이미 무효가 된 요청으로 한 번 움직일 수 있다. 기존 `floor`가 늦은 요청을 거부해도, 이미 읽어 둔 판단까지 취소하지는 않는다.  
   **고칠 방법:** 재출발 출력과 정지 취소가 경합하지 않도록 최신 누름 번호·자리·정지 상태를 출력 결정에 연결하고, 센서 읽기 도중 정지를 주입해 검증한다.

4. **[치명] 같은 I2C가 막히면 장애물 판정과 정지 수단이 함께 막힌다.**  
   **근거:** `specs/05-obstacle-stop.md:74,82`; `missions/webabb.py:47,48,151,543,615,623`; `specs/04-line-tracer.md:97`.

   **고칠 방법:** 호출 지연 상한과 실제 고장 시 정지시간을 검증하고, 같은 버스를 사용할 수 없을 때의 정지 수단을 승인 조건으로 둔다.

5. **[높음] 반복 읽기를 새 측정으로 인정해 「1초 연속」을 보장하지 못한다.**

9. **[높음] 곡선 접근·회전·후진의 충돌은 한계 문장만 있고 운전 제한이 없다.**

14. **[높음] 장애물 대기 상태의 수동 전환을 잘못 표현하면 첫 방향 누름이 즉시 이동한다.**

21. **[중간] 성공 기준의 시간 측정이 실제 위험 구간을 잘라 낸다.**  
    **근거:** `specs/05-obstacle-stop.md:41,42,43,50`.  
    **시나리오:** 「첫 가까운 읽기→0 출력」 0.05초는 센서 갱신 대기와 실제 바퀴 정지를 제외한다. 「상자를 치운 순간」도 움직이기 시작한 때인지 빔 밖으로 완전히 나간 때인지 불명확하다. 1초 안에 넣었다 뺀 짧은 장애물이 읽기 사이에 빠진 경우도 따로 없다.  
    **고칠 방법:** 실제 경계 진입·새 측정·판정·네 바퀴 0 완료·물리 정지와, 완전 제거·해제 판정·첫 움직임을 각각 기록한다.

22. **[중간] 정면 상자 10회 성공으로 허용 가능한 운전 범위를 판정할 수 없다.**  
    **근거:** `specs/05-obstacle-stop.md:40,44,48`; `specs/04-line-tracer.md:87`; `log.md:20`.  
    **시나리오:** 얇은 물체·비스듬한 면·움직이는 물체는 합격 기준 없는 기록만 남기고도 통과한다. 30초 대기 한 번은 반복 재출발이나 장시간 통합 부하를 검증하지 않는다. **추정:** 쿨러 없는 Pi에서 블박 파일 교체와 향후 YOLO 부하가 겹치면 지연이 커질 수 있다.  
    **고칠 방법:** 물체·각도·속도·배터리·반복 대기·통합 부하별 시험과 실패 시 운전 제한을 정한다.

23. **[중간] 다리 시험 요구와 사람 몸 시험 금지가 충돌한다.**  
    **근거:** `specs/05-obstacle-stop.md:48,54`.  
    **시나리오:** 성공 기준에는 다리를 앞에 대라고 쓰고 안전에는 손 외 사람 몸으로 시험하지 말라고 쓴다. 못 보는 물건 시험이 주행 중인지 정지 상태인지도 없어 시험자가 위험한 쪽으로 해석할 수 있다.  
    **고칠 방법:** 인체 대신 모형을 쓰고, 감지 한계 측정은 바퀴가 움직이지 않는 상태로 명시한다.

24. **[중간] 화면·불빛이 실제 정지 상태와 출발 권한을 잘못 전달할 수 있다.**  
    **근거:** `specs/05-obstacle-stop.md:22,83`; `missions/webabb.py:552,578,672`; `missions/webabb/index.html:144,169,245`.  
    **시나리오:** 현재 화면은 바퀴 출력 0이면 일반 「정지」로 표시한다. 대기 중 `_line()`을 생략하면 직전 동작·센서 표시가 남을 수 있고, 출력이 계속 0이면 `out_name`도 갱신되지 않는다. 응답 순서 검증도 없어 늦은 응답이 새 표시를 덮을 수 있다. 비상정지·줄 없음으로 대기가 끝났을 때 빨간 불을 어떻게 처리할지도 없다.  
    **고칠 방법:** 서버 상태에 대기·재출발 권한·자료 나이·상태 순번을 넣고, 모든 종료 경로의 화면·불빛·부저 처리를 정한다.

**이대로 구현을 시작해도 되는가: 아니오.** 자동 재출발의 안전 조건, 측정값의 유효성, 정지 우선권과 라인 상태 복귀 규칙을 먼저 확정해야 한다.
