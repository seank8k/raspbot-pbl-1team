# 리뷰 06 · 사람·STOP 인식 상태 화면

날짜: 2026-11-06 · 작성: Codex

지시서: [06-person-stop.md](../../specs/06-person-stop.md)

검토 결과: 화면 표시 수정과 서버 적용 확인 완료. 실제 카메라 인식 및 주행 동작은 조원 확인 대기.

- 요청: 사람과 STOP을 인식하는지 알기 어렵다는 문제를 해결하고 진행상황을 MD로 남김.
- 원인: 이전 화면은 감지했을 때만 STOP 알림이 나타나 미감지·준비 중·오류·통신 끊김을 구분하기 어려웠음.
- 완료: 영상 아래에 **사람 / STOP 표지판** 상태를 항상 표시. 감지됨(65% 이상), 약하게 감지(정지 기준 미달), 감지 안 됨을 구분하며 검출 시 확신도 표시. 오류·준비·꺼짐·오래된 결과·통신 실패는 확인 불가로 표시하고 이전 검출 박스를 지움.
- 완료: 실제 주행 여부와 현재 정지 이유를 인식 상태 바로 아래에 표시. 인식 요청은 중복 없이 처리하고 1초 통신 제한으로 오래된 감지 표시가 남지 않게 함.
- 적용: 지시서 06을 먼저 갱신하고 `missions/webabb/index.html`만 서버에 교체. 서버 재시작·바퀴/서보 명령 없음. 정지·재출발·인식 기준 변경 없음.
- 검증: JavaScript 문법 검사 및 표시 상태 9가지 통과. 실제 포트5000 HTTP200, 응답 HTML과 배포 파일 바이트 일치. 처음 포트8000 확인은 연결 거부됐으며 실제 포트로 재확인 완료.
- 증거: `results/2026-11-06-recognition-display-check.txt`, `results/2026-11-06-recognition-display-server.txt`. 백업: 라즈봇의 `results/backups/recognition-display-20261106/`.
- 다음 확인: 조원이 웹 화면을 새로고침한 뒤 사람과 STOP을 각각 카메라 앞에 보여 주고 상태·확신도가 바뀌는지 확인. 실제 인식 성공률과 정지/재출발 동작은 이번 화면 검사만으로 확인하지 않았음.
- 현재 기준: 서버 마지막 확인 PID3435 (`--gesture-start-stop-only`), STOP3초 정지 후 재출발/같은 표지판5초 무시, 사람 사라진 뒤1초 재출발. 다른 정지 이유가 남으면 출발하지 않음. 장애물 유효 측정 상한5000mm 복구 완료, 카메라 마지막 서보2 명령5°. 아래 과거 기록의800mm·인식 꺼짐·카메라25°는 이전 상태임.
