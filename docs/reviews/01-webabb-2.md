**진행 방향 수정 제안**

1. **지시서부터 보완한다.** 동시 입력, keyup 유실, 영상 상실, 자리 재접속, 연속 주행 한계, 고장 때의 재허가 조건을 조원이 정한다. 상자 위 시험과 AGENTS 수칙도 맞춘다.
2. **모터 제어를 한 주체로 모은다.** HTTP 요청은 직접 바퀴를 쓰지 않고, 자리·명령 순서·유효기간·정지·종료를 같은 제어 흐름에서 판단하게 설계한다.
3. **정지 실패를 감지하고 잠그는 구조를 만든다.** I2C 오류 전달, 네 바퀴 정지 시도, 제한된 재시도, 주행 금지 상태를 마련한다. 보드 자체 워치독과 독립 차단 수단도 확인한다.
4. **실물 없이 깨뜨리는 시험을 먼저 한다.** 주행→정지 순서 뒤집기, 자리 반납 중 옛 요청 실행, 요청 적체, I2C 지연·실패, 워치독 예외, 종료 중 요청을 시험한다. 실제 브라우저에서는 두 키·다중 터치·잠금·탭 전환·새로고침을 확인한다.
5. **카메라를 켠 dry 시험을 통과시킨다.** 영상 전송량·프레임 나이·조종 지연을 함께 재고, 중복 스트림·느린 연결·카메라 분리·통신 복구 뒤에도 오래된 주행이 살아나지 않는지 확인한다.
6. **그다음 실물 시험을 한다.** 수칙에 맞는 사용자 확인을 받은 뒤 바퀴를 띄운 시험부터 진행하고, 이후 바닥에서 조작과 바퀴를 함께 촬영해 성공 기준을 측정한다. 결과는 지시서에, 문제는 `log.md`에 기록한다.
