|---|---|---|
| 키보드 조종이 펄스처럼 끊김 | Windows 첫 키 반복 대기(0.43~0.58초)가 teleop 자동 정지(0.6초)에 아슬아슬 | 재입력 시간을 가장 짧게 → 0.25~0.32초 · 끊김 0번 (`tools/key_gap_test.py`로 측정) |

## 5. 웹 조종 기능 (`specs/01-webabb.md` · `missions/webabb.py`)

### 정한 것 (조원 결정)
- 브라우저(노트북 · 휴대폰)에서 **버튼 + 키보드 W A S D Q E**로 조종, **카메라 화면** 표시
- **누르고 있는 동안만** 움직임 · 속도 **처음 120**, 슬라이더로 40~150
- 앞/뒤 + 왼쪽/오른쪽 = **대각선**, 왼쪽 + 오른쪽 = 안 움직임, **정지 버튼** 따로
- 화면이 꺼지거나 새로고침하면 정지 · 영상이 멈추면(0.8초) 정지
- **먼저 접속한 한 대만** 조종 (휴대폰 1 + 컴퓨터 1 동시 조종을 잠깐 만들었다가 되돌림) · 접속 비밀번호 없음
- 주소: `http://raspibot-01.local:5000`

### 진행
1. 기획서 작성 → 1차 구현 → 서버 응답 점검
2. **Codex 적대적 리뷰** (`docs/reviews/01-webabb.md`, 19건): 「정지 뒤 늦게 온 이동으로 재출발」, 「정지 실패를 정지로 처리」 등 치명 문제 → **제어부 다시 만들기**
3. 다시 만든 구조
   - 바퀴 명령은 제어 스레드 하나만 씀 · 메시지마다 순번 · 누름 번호 → 멈춘 뒤엔 **새로 눌러야** 움직임
   - 드라이버가 I2C 오류를 삼키는 것을 확인 → 같은 명령을 직접 보내 오류를 잡음 · 정지 실패 시 잠금 + 재시도
   - 감시 스레드 · 누구나 쓸 수 있는 비상정지 · 토큰은 쿠키로 · 영상 나이 표시
4. **깨뜨리는 시험 32/32 통과** (`--dry`, 바퀴 안 돎) · 영상 멈춤 정지 · Ctrl+C 정지 확인
5. 실제 브라우저 확인 (`--dry`): 대각선 4 · 회전 · 새로고침 정지 · 비상정지 0.002초 · 아이폰 접속
   - 아이폰이 핫스팟에서 **IPv6로만** 통신 → 서버를 IPv4 · IPv6 둘 다 받게 고침

### 아직 안 한 것
- **실제 바퀴 시험** (상자 위 → 바닥) — 실제 바퀴 모드로 서버까지 켰으나, 휴대폰이 다른 핫스팟에 붙어 있어 시험 전에 종료
- 「프로그램이 강제로 죽었을 때 보드가 스스로 멈추는지」 실험
- 카메라 지연 측정 · 성공 기준 표 채우기
